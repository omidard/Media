# remap_components reports

Produced by `python3 tools/stages/remap_components.py --out <dir>` over the full
corpus (13,515 media, 665,582 components; ~55 s).

* `tier_distribution.json` — evidence-tier counts before and after the stage.
* `review_queue.tsv` — 305 identity corrections the corrected mapper PROPOSES but
  that the stage deliberately did not apply, because they change which compound a
  row is rather than which enantiomer. Each needs a curator decision. Two real
  defects in this pass were found by reading this file rather than by a test.
* `refusals.tsv` — the ambiguity list: 274 distinct source strings covering 1,018
  components where the mapper declined to choose, with the reason and the kind
  (`no_match`, `racemate`, `stereo_conflict`, `chemically_ambiguous`). This is the
  honest record of what the resource does not know.

The per-component change ledger (`component_remap_ledger.tsv.gz`, ~3.7 MB, one row
per changed component with old and new id, exchange, confidence, tier, the
correction ids applied and a flux-consequence flag) is NOT checked in — it is
regenerated by the command above and would otherwise go stale against the data.

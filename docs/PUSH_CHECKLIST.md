# Push checklist

Everything here is a command whose output decides the answer. Run them from the
repository root, in this order.

## Before the push

```bash
make preflight      # registry, CI trigger paths, sample chain, tests, derived, manifest/tree
make reproduce      # the chain rebuilds the shipped corpus from the committed input
make size           # what the published site weighs against GitHub Pages' 1 GiB limit
git status --porcelain -uall        # must be empty: preflight is idempotent
```

`make preflight` must leave the tree clean. `make derived` no longer stamps a fresh
`built_utc` into the six `data/web` payloads and `data/MANIFEST.json` on every run —
the stamp dates the build that last *changed* the payload — so a rebuild of unchanged
data writes no bytes, and a `git diff` under `data/` after a rebuild means the data
actually moved.

## After the push: publish the bulk exports

**This is still open.** `media.sqlite.gz` and `media.jsonl.part01.gz` (172.8 MiB of
re-encoded corpus) left the published site so it would fit under the Pages limit, and
the `data-v1` release that is meant to carry them **has never been created**. Until
it is:

* `data/api/manifest.json` → `bulk_download.status` reads `planned`;
* README, `API.md`, `openapi.yaml` and the Makefile tell readers to build the files
  locally and say the hosted download does not exist yet;
* `pymediadb.iter_full_records()` reads that status, skips the release and streams
  every record from the per-medium endpoint instead of raising on a 404.

Nothing is unreachable in the meantime — the files rebuild offline from the committed
corpus — but the release should still be created. It needs an authenticated `gh`
(there is none on the build host today) and the branch pushed, because the tag needs a
commit on the remote to point at.

```bash
make release-assets                     # -> dist/api/*.gz + manifest.json + RELEASE_NOTES.md
gh release create data-v1 dist/api/*.gz --repo omidard/Media \
  --title 'MediaDB bulk exports (data-v1)' --notes-file dist/api/RELEASE_NOTES.md

# verify, do not assume — each asset must answer 200 with the size the notes state
for f in media.sqlite.gz media.jsonl.part01.gz; do
  curl -sIL -o /dev/null -w "$f %{http_code} %{size_download}\n" \
    https://github.com/omidard/Media/releases/download/data-v1/$f
done
```

Then, and only after those return 200:

1. set `RELEASE_STATUS = "published"` in `tools/build_api_exports.py`;
2. `make derived` (rewrites `data/api/manifest.json` — `bulk_download.status`
   flips, and the wording that says the release does not exist goes with it);
3. `make test` — `tests/test_claims.py` checks that every document, the published
   manifest and the client agree with that constant, in both states;
4. commit `data/api/manifest.json`, `data/MANIFEST.json` and
   `tools/build_api_exports.py`, plus the documents you updated, and push.

The release note is generated by `make release-assets`, not typed: it carries the
asset sizes and sha256s, the repository commit, the `data/media` corpus digest and
the licence position measured in the same run that built the bytes.

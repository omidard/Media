Methods and limitations

What a record here is, and what it is not.

Every medium here is somebody else's formulation, re-encoded against a standard set of exchange reactions so a genome-scale model can read it. Each assumption in that encoding is defined below, with the field that records it and the count it applies to.

How a component's identity is decided

Each component in this library is a claim that a named ingredient is a particular molecule, and for nearly all of them that it is a particular BiGG exchange reaction. The record keeps the evidence behind each of those claims: twelve recorded evidence tiers, grouped into six classes and ordered by the strength of the evidence.

A name match records a string, not a chemical identity.

For most components the deciding evidence is a name string. A name match cannot detect that a source's "Cystine" is a different molecule from L-cysteine, that a "MUFA 18:1" measurement pooled every 18:1 isomer, or that "Vitamin B-6" names a vitamer group and not pyridoxine. A component whose class was collapsed onto one representative molecule carries the class or assertion tier.

Recorded tierClassComponents

The class states how far the identity can be trusted. Structure-verified rests on a structural cross-reference and identifier-verified on a database id the source itself supplied; name-matched rests on a string; class or assertion records a deliberate simplification; pipeline-derived components are not in the source at all; unresolved components carry no identity claim. Every component carries its class, in the browser and in the data, and can be filtered by it.

Where the exchange ids land

A component carries a BiGG exchange reaction a genome-scale model can accept. Nearly every one does. The exceptions fall into two states, both counted here and named on the record that holds them.

A fallback id is not a near miss. EX_cpd15137_e is a ModelSEED identifier in exchange position: it names a real compound, and no BiGG model has a reaction by that name. The component's mapping_note states this, the record counts it in n_nonbigg_fallback, and the copy-to-COBRApy block skips any exchange the model does not carry. A component with no exchange at all is an ingredient whose identity was never established, or an undefined mixture with no single molecular identity to establish; both are listed on the record.

What each coverage fraction divides by

Three fields can be read as coverage and they divide by different denominators. All three ship on every record. Only pct_covered_source is displayed on this site.

FieldWhat it divides byStatus
pct_covered_source The ingredients the cited source itself states. Pipeline-derived components are excluded from both the numerator and the denominator. The number this site displays.
pct_sourced_components_with_bigg_id Of the components the source states, the share that reached a BiGG metabolite id rather than a non-BiGG fallback or nothing. Its denominator is components the record already carries, not the source's ingredient list, so it is not a coverage measure. Published on each record; null where the source states no ingredient list. Exports that predate this release name the same field pct_covered_observed.
pct_covered Every component the record ends up with, including the ones the pipeline supplies. That ratio is necessarily near 100% and carries no information. Deprecated. Present in the data for compatibility with existing consumers; not displayed on this site.
Source coverage is sometimes a ceiling, not a point estimate.

Some records count the source ingredients that were replaced by derived components as a floor, so the true denominator is at least that large and the percentage is at most the one shown. Those records say "at most" beside the number.

Components the source never stated

A large minority of the component records in this library are supplied by the pipeline and are not read from a source. A derived component has one of three origins, and none of them is a measurement:

  • Complex-ingredient decomposition. A recipe says "beef extract"; a standard composition reference is used to expand that into amino acids, nucleotides, vitamins and minerals. The recipe never listed those molecules.
  • Hydrolysate approximation. The same idea for peptones, tryptone, yeast extract and casein hydrolysates, which are undefined mixtures by construction.
  • Injected mineral and oxygen base. Water, protons, phosphate, sulfate, ammonium and trace metals are added so a model is not starved of an element the source took for granted. This is a modelling convention, not the recipe.
Where a derived component appears.

Derived components are part of every medium that carries them. They are marked with a dashed rule everywhere they appear, excluded from every source-coverage number, and written into their own commented section of the copy-to-COBRApy block, so a medium can be loaded with or without them. Deleting them makes many media infeasible in flux balance analysis.

Bounds are not measured uptake rates

Almost every lower bound in this library is a presence placeholder: it encodes "this is in the medium", not "this is taken up at this rate". Treat a bound as a switch, and set your own numbers before interpreting a flux.

Where an amount exists it is published verbatim in quantity, with its basis beside it: a mass per 100 g of food is not a concentration, and converting one into the other requires a volume of medium that nobody measured. That conversion is not performed, so concentration_mM is null wherever it is not derivable and the component carries a concentration_block_reason naming what blocks it.

Two media, one model input

A record carries a name, a source, a citation and a licence. A model reads none of them. What reaches the solver is the set of (exchange reaction, lower bound, upper bound) triples, and by that measure a large fraction of this library is degenerate: choosing between two of these media changes nothing a solver can see.

A duplicate model input is labelled on both records.

Measuring the library.

Two things drive it. Most bounds in this library are presence placeholders rather than measured rates, so two recipes that list the same compounds at different amounts collapse onto the same constraint set. And many formulations genuinely differ only in something a medium record does not encode: an agar concentration, a pH, a preparation step, a sterilisation regime.

Which paper a formulation came from is a real difference even when the constraint set is not, so each record carries its own provenance and citation. The record sheet names the other media that produce the identical model input, the catalog carries n_media_with_identical_model_input and model_input_signature per record, and the complete groups are published at data/web/twins.json. Adding each component's source-stated concentration to the comparison, a stricter test than any solver applies, leaves most of them still indistinguishable.

This is a different measurement from composition_identical_to, which is written for records whose quantitative signature matches inside one base-medium family. That field covers 1,497 records. The comparison here is library-wide and ignores family, name and source entirely.

Oxygen regime

The oxygen regime decides whether you open or close EX_o2_e, which is the single most consequential bound in an FBA medium. It has four states here, and one of them is "unknown".

Unknown is its own state.

A record whose source does not state an oxygen regime is unknown, in the table, in the filter and on the record. Unknown is a state of the field and not a synonym for anaerobic. A facultative regime is a property of the medium and not evidence that the organism is an aerobe.

Base-medium families

A family groups the variants of one base medium, so "LB" is one entry with variants and not dozens of unrelated rows. Each record carries the method its family was decided by, in family.method.

A family is a naming grouping. It is not a claim that the variants are interchangeable.

Most assignments come from the medium's name. Where a record's composition could also be checked against the family's canonical scaffold, the record carries that corroboration score; where it could not, it carries the reason the check was unavailable. Two records in one family can differ by a carbon source, by strength, by pH, or by being broth against agar, and the families view lists those differences per variant.

Licensing is per source, not per repository

There is no blanket data licence here. Each record carries the terms of the source it came from, and some records come from sources that grant no commercial use. Every record ships, labelled, and the browser can filter for the commercially usable subset.

The 471 MediaDB (ISB) records.

The only statement on the upstream page (read 2026-09-06, first-party) is "(c) 2014, Institute for Systems Biology, All Rights Reserved". No reuse grant of any kind is offered, and redistribution permission has not been obtained. These records are published, labelled all-rights-reserved, marked commercial_use_ok: false and excluded from the commercially usable subset. They hold the largest single share of the non-null concentration values in the library. If you need a subset you can redistribute, filter them out.

Withdrawn identifiers

A withdrawn identifier names a medium that is no longer served by the browser or the API. Withdrawn media are formulations whose cited source does not contain the composition, whose source could not be located, or that are not growth media. A withdrawn identifier is not reassigned and no other record is a substitute for it.

Opening a withdrawn identifier in the browser returns a tombstone naming it.

The complete set of withdrawn identifiers, each with a reason field, is published as data/web/tombstones.json.

Reproducibility

The corpus is a frozen snapshot.

data/media/*.json is the authoritative copy of the library and cannot be regenerated from its original inputs: the raw upstream payloads behind the literature-derived records were not retained, and a fresh extraction would file different compositions under the same citations.

Corrections are applied as transform stages: a stage reads the corpus and writes a corrected corpus, and the chain of stages, run in a recorded order, is the pipeline. No correction is hand-edited into the data. make reproduce runs the whole chain from the committed baseline in data/_baseline/ and compares the result to the corpus that ships.

Public upstream sources (USDA, MediaDive, BiGG, MetaNetX) are checksummed into data/_sources/, so every mapping can be compared against the source it came from.

The limits, in one list

  1. Component identities mostly rest on a name string, not on chemistry. A name match cannot distinguish a vitamer group from a vitamer, or a fatty-acid class from an isomer.
  2. A large minority of component records are supplied by this pipeline and are not in the cited source. They are an approximation of an undefined mixture, or a modelling convention.
  3. Bounds are presence placeholders. No bound in this library is a measured uptake rate.
  4. Food records are built from a population-average nutrient analysis, not from a laboratory formulation. Their amounts are per 100 g of food; they are not a concentration and no conversion into one is published.
  5. Cross-references shown against a component describe the BiGG metabolite that was chosen. They were not used to choose it, so they cannot contradict it and they are not independent evidence.
  6. The corpus is a frozen snapshot and cannot be regenerated from its raw upstream inputs. Corrections are applied forward, as recorded transform stages.
  7. Records are not deduplicated by their model input, and a large fraction of the library is degenerate under it.
  8. Not every component reaches a BiGG exchange. A small number carry a fallback id no BiGG model will accept, and a smaller number carry none at all.
  9. Not every component carries a cross-reference. Where none is shown, none is recorded.
  10. A family assignment is usually a name match. It does not assert that the variants in a family are interchangeable.
  11. The oxygen regime is not recorded for some media. Unknown is not anaerobic.
  12. The licence is per source, and some records may not be used commercially. This resource cannot grant rights it does not hold.

How to cite

Cite the primary publication recorded in the record's provenance.citation, and, if the compilation itself was load-bearing for your result, name this resource and the release stamp shown at the top of this page. A record here is an encoding of somebody else's formulation, and the encoding is where the assumptions live.

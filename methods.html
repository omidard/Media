Methods and limitations

What a record here is, and what it is not.

This resource is a compilation. Every medium is somebody else's formulation, re-encoded against a standard set of exchange reactions so a genome-scale model can use it. That re-encoding introduces assumptions, and this page states them, with counts, so you can decide what to trust.

How a component's identity is decided

Each component in this library is a claim that a named ingredient is a particular molecule, and for nearly all of them that it is a particular BiGG exchange reaction. The record keeps the evidence behind each of those claims: twelve recorded evidence tiers, grouped into six classes and ordered by the strength of the evidence.

A name match is a fallback, not a confirmation.

For most components the deciding evidence is a name string, not a chemical identity check. A name match cannot detect that a source's "Cystine" is a different molecule from L-cysteine, that a "MUFA 18:1" measurement pooled every 18:1 isomer, or that "Vitamin B-6" names a vitamer group rather than pyridoxine. Where the pipeline collapses a class onto one representative molecule, the component says so in the class or assertion tier rather than presenting the assumption as a measurement.

Recorded tierClassComponents

Read the classes as how far the identity can be trusted. Structure-verified rests on a structural cross-reference and identifier-verified on a database id the source itself supplied; name-matched rests on a string; class or assertion records a deliberate simplification; pipeline-derived components are not in the source at all; unresolved components carry no identity claim. The evidence class is on every component, in the browser and in the data, so a record can be filtered by it.

Where the exchange ids land

The point of this resource is that a component carries a BiGG exchange reaction a genome-scale model can accept. Nearly every one does; the exceptions are counted and listed rather than rounded away.

A fallback id is not a near miss. EX_cpd15137_e is a ModelSEED identifier in exchange position: it names a real compound, and no BiGG model has a reaction by that name. The component's own mapping_note says so, the record counts it in n_nonbigg_fallback, and the copy-to-COBRApy block will not silently succeed with it. The components with no exchange at all are ingredients whose identity was never established, or undefined mixtures that have no single molecular identity to establish; they are listed, never dropped.

What each coverage fraction divides by

Three different fractions can be called "coverage" and they do not agree. This resource publishes all three and names what each divides by; only the first is displayed as a quality signal.

FieldWhat it divides byStatus
pct_covered_source The ingredients the cited source itself states. Pipeline-derived components are excluded from both the numerator and the denominator. The number this site displays.
pct_sourced_components_with_bigg_id Of the components the source states, the share that reached a BiGG metabolite id rather than a non-BiGG fallback or nothing. Its denominator is components the record already carries, not the source's ingredient list, so it is not a coverage measure. Published on each record; null where the source states no ingredient list. Older data exports name this field pct_covered_observed.
pct_covered Every component the record ends up with, including the ones the pipeline supplies. That ratio is necessarily near 100% and carries no information. Deprecated. Present in the data for compatibility with existing consumers; never rendered here as a quality signal.
Source coverage is sometimes a ceiling, not a point estimate.

Some records count the source ingredients that were replaced by derived components as a floor, so the true denominator is at least that large and the percentage is at most the one shown. Those records say "at most" beside the number.

Components the source never stated

A large minority of the component records in this library were supplied by the pipeline rather than read from a source. There are three reasons this happens, and none of them is a measurement:

  • Complex-ingredient decomposition. A recipe says "beef extract"; a standard composition reference is used to expand that into amino acids, nucleotides, vitamins and minerals. The recipe never listed those molecules.
  • Hydrolysate approximation. The same idea for peptones, tryptone, yeast extract and casein hydrolysates, which are undefined mixtures by construction.
  • Injected mineral and oxygen base. Water, protons, phosphate, sulfate, ammonium and trace metals are added so a model is not starved of an element the source took for granted. This is a modelling convention, not the recipe.
They are kept, never deleted.

Removing them would make thousands of media infeasible in flux balance analysis, and that failure would be blamed on the model. So they ship, they carry a dashed marker everywhere they appear, they are excluded from every source-coverage number, and the copy-to-COBRApy block puts them in their own commented section so you can delete them yourself.

Bounds are not measured uptake rates

Almost every lower bound in this library is a presence placeholder: it encodes "this is in the medium", not "this is taken up at this rate". Treat a bound as a switch, and set your own numbers before interpreting a flux.

Where an amount exists it is published verbatim with its basis: a mass per 100 g of food is not a concentration, and converting one into the other requires a volume of medium that nobody measured. This resource does not perform that conversion, and it does not present a mass fraction in the same column as a molar concentration.

Two media, one model input

A record carries a name, a source, a citation and a licence. A model reads none of them. What reaches the solver is the set of (exchange reaction, lower bound, upper bound) triples, and by that measure a large fraction of this library is degenerate: choosing between two of these media changes nothing a solver can see.

Duplicates are labelled, never merged.

Measuring the library.

Two things drive it. Most bounds in this library are presence placeholders rather than measured rates, so two recipes that list the same compounds at different amounts collapse onto the same constraint set. And many formulations genuinely differ only in something a medium record does not encode: an agar concentration, a pH, a preparation step, a sterilisation regime.

Which paper a formulation came from is a real difference even when the constraint set is not, so each record keeps its own provenance and citation. The record sheet names the other media that produce the identical model input, the catalog carries n_media_with_identical_model_input and model_input_signature per record, and the complete groups are published at data/web/twins.json. Adding each component's source-stated concentration to the comparison, a stricter test than any solver applies, leaves most of them still indistinguishable.

This is a different measurement from composition_identical_to, which is written for records whose quantitative signature matches inside one base-medium family. That field covers 1,497 records. The comparison here is library-wide and ignores family, name and source entirely.

Oxygen regime

The oxygen regime decides whether you open or close EX_o2_e, which is the single most consequential bound in an FBA medium. It has four states here, and one of them is "unknown".

Unknown is its own state.

A record whose source does not state an oxygen regime is counted as unknown, in the table, in the filter and on the record; it is never folded into anaerobic. A facultative regime is shown as facultative and is not evidence that the organism is an aerobe.

Base-medium families

A family groups the variants of one base medium so that "LB" is one thing with variants rather than dozens of unrelated rows. How each family was decided is recorded on the record and shown in the browser.

A family is a naming grouping. It is not a claim that the variants are interchangeable.

Most assignments are made from the medium's name. Where the pipeline could also check the record's composition against the family's canonical scaffold it publishes that corroboration score, and where it could not it publishes the reason instead of a guess. Two records in one family can differ by a carbon source, by strength, by pH, or by being broth against agar. The families view shows what differs rather than averaging it away.

Licensing is per source, not per repository

There is no blanket data licence here. Each record carries the terms of the source it came from, and some records come from sources that grant no commercial use. Every record ships, labelled, and the browser can filter for the commercially usable subset.

The 471 MediaDB (ISB) records.

The only statement on the upstream page (read 2026-09-06, first-party) is "(c) 2014, Institute for Systems Biology, All Rights Reserved". No reuse grant of any kind is offered, and redistribution permission has not been obtained. The records are kept rather than deleted: they are the single largest seam of quantitative data here, holding the largest single share of the non-null concentration values. They are labelled all-rights-reserved, marked commercial_use_ok: false and excluded from the commercially usable subset. If you need a subset you can redistribute, filter them out.

Reproducibility

The corpus is a frozen snapshot.

The raw upstream payloads behind the literature-derived records were not retained, so data/media/*.json is the authoritative copy: the library cannot be regenerated from its original inputs. Re-running the literature extraction would file different compositions under the same citations, so it is not run.

Corrections are applied as transform stages: a stage reads the corpus and writes a corrected corpus, and the chain of stages, run in a recorded order, is the pipeline. No correction is hand-edited into the data. make reproduce runs the whole chain from the committed baseline in data/_baseline/ and compares the result to the corpus that ships. The payload this page reads is built by tools/build_web_payload.py, which asserts its own numbers against the corpus before the payload is written.

Public upstream sources (USDA, MediaDive, BiGG, MetaNetX) are checksummed into data/_sources/, so every mapping can be compared against the source it came from.

Records withdrawn from the library

A record is withdrawn when a verification pass against its cited source cannot support it: the composition promises ingredients the source does not contain, the source cannot be found, or the entry is not a growth medium at all. Withdrawn records are not served by the browser or the API. They are listed here with the reason, because a withdrawn record may still be cited elsewhere and its identifier deserves an answer.

This count has no denominator.

The verification pass recorded what it rejected but not how many records it assessed, so the number below is a count and cannot honestly be turned into a rate.

The limits, in one list

  1. Component identities mostly rest on a name string, not on chemistry. A name match cannot distinguish a vitamer group from a vitamer, or a fatty-acid class from an isomer.
  2. A large minority of component records were supplied by this pipeline and are not in the cited source. They are an approximation of an undefined mixture, or a modelling convention.
  3. Bounds are presence placeholders. No bound in this library is a measured uptake rate.
  4. Food records are built from a population-average nutrient analysis, not from a laboratory formulation. Their amounts are per 100 g of food; they are not a concentration and this resource does not convert them into one.
  5. Cross-references shown against a component describe the BiGG metabolite that was chosen. They were not used to choose it, so they cannot contradict it and they are not independent evidence.
  6. The corpus is a frozen snapshot and cannot be regenerated from its raw upstream inputs. Corrections are applied forward, as recorded transform stages.
  7. Records are not deduplicated by their model input, and a large fraction of the library is degenerate under it.
  8. Not every component reaches a BiGG exchange. A small number carry a fallback id no BiGG model will accept, and a smaller number carry none at all.
  9. Not every component carries a cross-reference. Where none is shown, none is recorded.
  10. A family assignment is usually a name match. It does not assert that the variants in a family are interchangeable.
  11. The oxygen regime is not recorded for some media. Unknown is not anaerobic.
  12. The licence is per source, and some records may not be used commercially. This resource cannot grant rights it does not hold.

How to cite

Cite the primary publication recorded in the record's provenance.citation, and, if the compilation itself was load-bearing for your result, name this resource and the release stamp shown at the top of this page. A record here is an encoding of somebody else's formulation, and the encoding is where the assumptions live.
